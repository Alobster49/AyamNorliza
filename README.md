# AyamNorliza Ops

MOD-01 (Tenant, identity and access) implementation for the AyamNorliza chicken-coop
operations platform. Architecture follows the master blueprint in
[`documentation/Planing/00-foundation.md`](documentation/Planing/00-foundation.md):
Next.js App Router modular monolith on Supabase (Postgres + Auth + Storage + Edge
Functions + Realtime), with PostgreSQL RLS as the only authorization boundary the
server can fully trust.

## Status

Phase 1, vertical slice. This commit lands the foundation: project scaffold,
Supabase clients, schema, RLS, audit triggers, and seed. UI routes, server
actions, email and Edge Functions follow in subsequent passes (see plan §12).

## Layout

```
src/
  app/                 # Next.js App Router (Server Components by default)
  components/          # shadcn/ui primitives, app shell, providers
  features/
    identity-access/   # MOD-01 feature module
  lib/
    supabase/          # browser, server, admin clients + session proxy
    auth/              # requireUser, requireOrgMember, requireReauth, mfa
    audit/             # audit event helpers
    email/             # Resend wrapper + templates
    notifications/     # multi-channel dispatch
    env.ts             # validated env access (server-only for sensitive vars)
  types/
    database.generated.ts  # generated by `npm run db:types`
supabase/
  migrations/          # versioned SQL
  functions/           # Edge Functions (Deno)
  tests/rls/           # pgTCT-style RLS policy tests
e2e/                   # Playwright tests
```

## Prerequisites

- Node.js 20 LTS
- npm (or pnpm)
- Supabase CLI (`brew install supabase/tap/supabase`)
- Docker (for local Postgres / Edge Functions)

## Setup

```bash
cp .env.local.example .env.local
# fill in Supabase URL, anon key, service role key, RESEND_API_KEY, etc.
npm install
supabase start
npm run db:reset          # applies migrations + seed
npm run db:types          # generates src/types/database.generated.ts
npm run dev
```

## Security

- `SUPABASE_SERVICE_ROLE_KEY` and `SUPABASE_DB_URL` are server-only. `src/lib/env.ts`
  refuses to expose them; `next.config.mjs` whitelists browser env vars explicitly.
- `src/lib/supabase/admin.ts` is the only module that touches the service-role
  client, marked `import "server-only"`, and exposes a narrow wrapper.
- Every tenant-owned table has RLS enabled with explicit `SELECT`/`INSERT`/
  `UPDATE`/`DELETE` policies and a corresponding test in
  `supabase/tests/rls/`.
- `audit_log` is append-only: an `audit_log_no_mutate` trigger blocks
  `UPDATE`/`DELETE` for all roles.

## Internationalisation

The app ships English (`en`) and Bahasa Melayu (`ms`). Every URL carries a
locale prefix: `/en/...` or `/ms/...`. A bare URL redirects to the visitor's
saved locale, or English if they have none.

- Strings live in `src/messages/en.json` and `src/messages/ms.json`. `en.json`
  is the source of truth; both files must have the same keys, and
  `src/lib/i18n/catalog.test.ts` fails the build if they drift.
- Read them with `useTranslations('namespace')` in client components and
  `await getTranslations('namespace')` in server components. Keys are
  typechecked — a typo fails `npm run typecheck`.
- Import `Link`, `useRouter`, and `usePathname` from `@/i18n/navigation`,
  never from `next/link` or `next/navigation`, for any new code. The plain
  versions still work (the middleware 307s a bare path to its locale-prefixed
  form using the cookie), but cost a redirect hop and resolve the locale from
  the cookie rather than the URL. Phase 1 converted the auth pages and shared
  chrome to the locale-aware versions; other surfaces still use bare paths.
  Phases 2–4 convert the rest, per surface, without a blanket sweep. An ESLint
  rule (`eslint.config.mjs`, scoped to `src/app/[locale]/**`) blocks new
  violations under that path so this doesn't regress further while the
  conversion is incomplete.
- Never concatenate translated strings. Use ICU placeholders:
  `t('workspaceSuffix', {section})`, not `t('workspace') + section`.
- New BM copy follows `docs/i18n-glossary.md` (glossary is provisional pending staff confirmation).
- Database values stay English. Only display labels are translated.
