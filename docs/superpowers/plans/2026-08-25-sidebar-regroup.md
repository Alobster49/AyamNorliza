# Sidebar Regroup (Sales → Sales + Fulfillment) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split the owner sidebar's 10-item "Sales" group into "Sales" (5 sales pages) and a new "Fulfillment" group (5 logistics pages).

**Architecture:** The sidebar groups are pure data in `routeGroups` inside `dashboard-shell-model.ts`; the UI renders whatever that model returns. Splitting the array plus adding one translation key per locale is the whole change. No routes, segments, or page titles change.

**Tech Stack:** Next.js (App Router), next-intl (auto-generates `en.d.json.ts`), Vitest.

## Global Constraints

- Pure regroup: no renames, no href/segment changes, no icon or behavior changes.
- New section key: `sections.fulfillment` — EN label `Fulfillment`, BM label `Logistik` (user-approved).
- Fulfillment item order (daily flow): Warehouse tasks, Dispatch, Loading, Delivery runs, Delivery setup.
- Staff-only "Warehouse" branch (inventory/logistics roles) must stay unchanged.
- `src/messages/en.d.json.ts` is auto-generated by next-intl ("do not edit directly") — it regenerates when `next dev` or `next build` runs. Do not hand-edit it.
- Working tree has unrelated modified files — commit ONLY the files this plan names (`git add` exact paths, never `-A`).
