# My Leave redesign — Balance Ring + card history (concepts Nº1 + Nº4)

Date: 2026-08-29
Status: approved (concept panel: "My Leave, Five Ways" artifact)

## Goal

Presentation-only redesign of the My Leave page (`/[locale]/(seller)/[organizationSlug]/leave`).
No server, schema, or `computeBalance` changes. Fixes the page's three real
weaknesses:

1. The equation card (CF + accrued − taken = balance) intimidates; the only
   question most users bring is "how many days do I have left?"
2. Six near-empty policy cards waste vertical space, especially on mobile.
3. The 6-column history table breaks down at 375px.

## Design

### 1. Balance Ring hero (`entitlement-header.tsx` rewrite)

- Card layout: SVG donut ring (left) + summary column (right); `asOf`
  select stays in the card header, year select stays in the page header.
- Ring: available / total, where `total = carryForward + accrued + credits`
  (the as-of pool). Fill fraction clamped to [0, 1]; `total <= 0` renders an
  empty track. Center shows `available` (keeps
  `data-testid="annual-available"` — e2e depends on it) over "of {total} days".
- Ring color by remaining fraction: emerald > 50%, amber 20–50%, red < 20%.
- Summary column: bold one-line status sentence, then chips:
  Carry forward · Accrued · Taken (+ credits chip only when credits > 0).
- "How it's calculated" collapsible (chevron trigger) reveals the current
  equation layout: CF (+ expiry date), accrued, taken split (base / CF),
  = balance. Nothing is deleted, only folded.
- Pending note (`pendingHeld > 0`) stays visible outside the fold, amber.
- `annualType == null` keeps the existing `noData` text.

### 2. Other-leave list (`policy-cards.tsx` rewrite)

- One card titled "Other leave" replacing the grid of small cards.
- Rows in a 1-col (mobile) / 2-col (`sm+`) grid: type name left,
  `available` number right, slim progress bar under (available / pool, same
  denominator rule; color from the existing `DOT_PALETTE` by `type.sort`).
- Upon-request types (entitlementDays null) render "Upon request" and no bar.
- `pendingHeld > 0` keeps the amber "{n} booked" note inline.

### 3. History cards on mobile (`leave-history.tsx`)

- `sm+`: existing table unchanged.
- Below `sm`: status-striped cards (left border color by status: pending
  amber, approved emerald, rejected red, cancelled muted). Card content:
  type dot + name, date range, day count, status badge, decision note
  (full text, no 200px truncation), Cancel button for pending.
- Filters and ConfirmDialog unchanged, shared by both renderings.
- Empty state gets a real CTA: dashed panel with "No leave requests yet"
  plus an "Apply Leave" button that opens the apply dialog
  (new `onApply` prop wired from `leave-client.tsx`).

### 4. Untouched

`whos-away.tsx`, dialogs, server actions, leave-model, routes, manage page.

## i18n

New keys under `hr.myLeave` (status sentence, "of {n} days", "How it's
calculated", chip labels reuse existing keys where possible) and
`hr.history` (empty-state CTA), in both `en.json` and `ms.json`.
`en.d.json.ts` is regenerated by next-intl during dev/build.

## Testing / gates

- e2e `hr-leave.spec.ts` must keep passing: preserves
  `data-testid="annual-available"` and the "Apply Leave" button name.
- Existing unit tests untouched (no logic change in leave-model).
- Gates: `npm run lint`, `npm run typecheck`, `npm run test`.
- Browser verification at 375px and desktop, both themes.

## Out of scope

Year-timeline strip (concept Nº2) — second phase once real leave data
exists. Manage/HR dashboard page. Any balance-math change.
